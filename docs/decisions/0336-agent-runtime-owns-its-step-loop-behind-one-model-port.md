# ADR 0336: The agent runtime owns its step loop behind one model port and three native providers

**Relations:** Amends [ADR 0098](0098-optional-agent-application-runtime.md) (the model-call execution boundary and tool projection inside the runtime) and [ADR 0206](0206-model-invocations-share-provider-evidence.md) (audited model invocations decorate `AgentModelDriver` and stream completions directly instead of wrapping an AI SDK `LanguageModel` with `wrapLanguageModel` and `generateText`). Applies [ADR 0008](0008-thin-wrappers.md), [ADR 0109](0109-provenance-aware-usage.md), [ADR 0122](0122-optional-peer-surfaces-are-proven-from-artifacts.md), [ADR 0197](0197-the-agent-runtime-is-a-product-behind-a-one-way-boundary.md) and [ADR 0199](0199-one-owner-per-name-and-one-way-per-job.md). Serves **I5**, **I6**, **I7**, **I8**, **I9**, **I10**, **I13**, **I15**.

## Context

ADR 0098 made the multi-step conversation loop the runtime's own: it disables SDK retries (`maxRetries: 0`), checkpoints structural stream parts, fences tools, enforces step barriers and admits every provider request durably. Yet `streamText` remained inside each attempt as an intermediary, forcing workarounds around every runtime guarantee:

- the options object crossed a double cast (`streamAgentTextBoundary`), leaving call options unchecked by TypeScript;
- the durable admission fence lived inside a `wrapLanguageModel` middleware that learned its call identity from a callback fired immediately before `wrapStream`;
- provider errors and the SDK's refusals of the runtime's own approval records left the same `doStream` stack, requiring a `WeakSet` origin mark plus `isInstance` checks on three SDK error classes;
- step barriers wrapped every tool's `execute`, `needsApproval`, `onInputAvailable` and `toolApproval` callbacks because the SDK scheduled tool execution;
- deferred-tool repair and per-call runtime context (`durability`, `reportProgress`) travelled through `WeakMap` registries keyed by object identity;
- the runtime mirrored SDK step state (`prepareStep` instruction overrides and previous step usage) so the provider journal recorded what was sent;
- history crossed three projections on the way out and two on the way back;
- the OpenRouter leaf wrapped `fetch` to `JSON.parse` and re-serialize every request body in order to preserve `strict: false`, `reasoning.effort: 'max'` and per-conversation `session_id`, and `sessionPerConversation` implicitly required invocation receipts (`AsyncLocalStorage`);
- the runtime's public declarations exposed AI SDK types (`LanguageModel`, `ToolSet`, `PrepareStepFunction`, `StopCondition`, `ModelMessage`, `LanguageModelUsage`), so every SDK major broke the runtime and every consuming project, even those never importing the AI SDK directly.

An audit across three independent consuming projects confirmed the full boundary needed to let applications migrate off external LLM SDKs cleanly in two steps (compatibility first, full native migration second) without putting application domain logic into Stitchkit (ADR 0002): all three need native structured-output completions (`responseFormat` + typed object validation) alongside the multi-step agent loop, two need leak-free driver lifecycle decoration (admission holds, credit reservations, attempt discard), and applications need direct native providers for OpenRouter, OpenAI, and Anthropic without pulling heavy vendor SDKs.

## Decision

1. **One model port (`AgentModelDriver`).** `stitchkit/agent-runtime` calls models exclusively through `AgentModelDriver.stream(request, signal)`: one provider step per call, no retries, no tool execution. A request carries normalized `AgentModelSystemMessage` instructions, canonical non-deprecated `AgentModelMessage` history (tagged `AgentModelFileData`, `text | file | custom` tool outputs, optional portable `AgentCacheControl`), active tool specs in JSON Schema 2020-12, optional `responseFormat` (`text | json-object | json-schema`), call settings, namespaced `providerOptions` and non-secret `correlation` (`conversationId`, `runId`, `invocationId`, `attemptId`, `step`). A stream emits ordered multi-block reasoning/text/tool parts (preserving per-block `AgentProviderEnvelope` for Anthropic signatures / `redacted_thinking`, OpenAI `encrypted_content`, and Gemini `thought_signature`), keepalive `{ type: 'ping' }` signals, and ends with one `finish` part carrying provenance-aware `AgentUsage`, optional `costDetails` (`promptCostUsd`, `outputCostUsd`, `isByok`), and `rawFinishReason`. Any throw out of `stream()` or while iterating `parts` is provider-origin by construction; transport/stream failures raise the single canonical `AgentProviderError` or `AgentProviderStreamCutError`.
2. **One native step loop and generic runtime primitives.** The runtime owns tool-call JSON parsing, input validation (`AgentUnknownToolError`, `AgentInvalidToolInputError` with PII-safe wire output), first-class deferred-tool repair, dependency-ordered and count-bounded scheduling (`stepBarriers` with optional `onPredecessorFailure: 'refuse'` fail-cascade and whole-step `beforeStepToolCalls` batch hook), WebCrypto HMAC-SHA256 tool-approval signing and verification (byte-compatible persisted payload format, executed once before retry attempts), bounded terminal continuations (`protocol.acceptTerminal` returning `boolean | { action: 'accept' | 'reject' | 'continue', message }` with `maxContinuations`), composable driver lifecycle decorators (`wrapModelDriver` / `composeModelDrivers` guaranteeing `onClose` on finish, error, or cancellation), and peer-free stateless completions (`completeText` / `completeObject` with multi-step tool support and typed `AgentStructuredOutputError`). No module in `packages/core/src/` imports `streamText` or `generateText`; no parallel loop ships beside it (I8).
3. **Audited ledger decorates the port.** ADR 0206's audited boundary becomes a decorator over `AgentModelDriver` that preserves `currentModelInvocationAttempt()` across `stream()` and streamed reads; plain completions collect text over `driver.stream()` with `ownedProviderStream` cleanup and receipts.
4. **Protocol-first peer-free transport and three native providers (I6, I7, I8, I10, I13).** Shared internal `provider-*` modules own Web Fetch-clean streaming HTTP (`redirect: 'error'`, bounded error/JSON reading, `Retry-After` parsing, secret redaction and surrogate-safe truncation), O(N) WHATWG SSE decoding with `maxEventBytes` and keepalive pings, history hygiene (`toWellFormed()` surrogate sanitization, orphan tool-call repair, empty output fallback, deterministic sorted-key JSON), cache-breakpoint budgeting (≤ 4 breakpoints, TTL order validation), JSON Schema normalization, and provenance-honest usage assembly. Three thin evolving peer-free provider leaves sit on top:
   - `stitchkit/agent-runtime/openrouter` (`openRouterProvider`, Chat Completions SSE, `looseTools` preserving explicit `strict: true`, `reasoning.effort: 'max'`, `session_id` from `correlation` without requiring `invocations`, `reasoning_details` & Gemini `thought_signature` round-trip, `cache_control` cap ≤ 4, BYOK `cost + upstream_inference_cost`, `native_finish_reason` guard, dropping `@openrouter/ai-sdk-provider`).
   - `stitchkit/agent-runtime/openai` (`openAiProvider`, OpenAI Responses API `POST /v1/responses`, stateless `store: false` + `include: ['reasoning.encrypted_content']`, `strict: false` default, `item_id` vs `call_id` separation, `role: 'developer'`, `text.format` structured outputs, `prompt_cache_key`, explicit I9 refusal of unsupported settings).
   - `stitchkit/agent-runtime/anthropic` (`anthropicProvider`, Anthropic Messages API `POST /v1/messages`, mandatory `maxOutputTokens` & `maxTokens > thinking.budgetTokens` fail-fast, verbatim multi-block `thinking`+`signature`+`redacted_thinking`, `computed` total `inputTokens = input_tokens + cache_read + cache_creation` per ADR 0109, `splitErrorToolResultImages`, `cache_control` cap ≤ 4 + TTL order, `output_config.format` with explicit refusal of schemaless `json-object`, `529 overloaded_error` retry classification).
   - `stitchkit/agent-runtime/ai-sdk` (evolving, optional peer `ai`) adapts any AI SDK `LanguageModel` (`fromAiSdkModel`) and `ToolSet` (`fromAiSdkTools`, normalizing legacy deprecated tool outputs at the boundary) without importing `streamText` or `generateText`.
   - Built chunks and `.d.ts` files for `stitchkit/agent-runtime`, `harness`, `coding-tools`, `testing`, `openrouter`, `openai`, `anthropic` and `stitchkit/tools` contain zero references to `ai`, `@ai-sdk/*` or `@openrouter/*`.
5. **One tool projection, zero aliases.** Neutral message and tool-output types live in `agent-parts/` (preserving ADR 0197's one-way core → runtime boundary). `mountAgentTools` and `defineAgentTool` in `stitchkit/tools` are the single peer-free tool construction and projection path (`AgentToolModelOutput` replaces the removed `RuntimeAgentModelOutput` alias); `mountAgent` in `stitchkit/tools/agent` adapts that projection into an AI SDK `ToolSet` emitting only non-deprecated `{ type: 'file', data, mediaType }` parts, so applications driving their own SDK loop are unaffected.
6. **I5 reading.** The multi-step conversation loop, three native wire drivers, and peer-free `completeText`/`completeObject` sit inside the separate `agent-runtime` product (ADR 0098, I15) backed by three independent consuming projects (I9). Stitchkit ships no UI hooks, no hardcoded model price tables, and no domain billing/skill/approval copy (ADR 0002, I4, I13). Additional providers or embeddings require separate consumer-backed ADRs.

## Consequences

- Breaking minor of `stitchkit/agent-runtime`, `stitchkit/tools` (`RuntimeAgentModelOutput` renamed to `AgentToolModelOutput`), and runtime leaves (`harness`, `openrouter`, `testing`): `AgentLanguageModelProvider` becomes `AgentModelDriverFactory`, `AgentResolvedModel.model` becomes `.driver`, `OpenRouterProviderSettings` uses `baseUrl`/`providerApiKeys`, `AgentRuntimeConfig` and `HeadlessAgentHarnessConfig` take `AgentToolSet`, and `prepareStep`, `stopPolicies`, `history.project`, `persistGeneratedFile`, and tool outputs use peer-free, non-deprecated runtime types. Existing `LanguageModel` and `ToolSet` callers migrate mechanically via `fromAiSdkModel` and `fromAiSdkTools`.
- Future AI SDK majors are contained to `stitchkit/agent-runtime/ai-sdk` and `stitchkit/tools/agent` and stop breaking the base runtime or the three native provider leaves.
- `internal/ai-sdk-typed.ts`, the `wrapLanguageModel` middleware pair, `providerOrigin` SDK-error checks, `runtime-call-context` and deferred-tool `WeakMap` bridges, step-barrier tool wrappers and the OpenRouter `fetch` body-rewriter are removed; bounded stream cleanup (`owned-provider-stream.ts`) remains as an I10 guard.
- Machine-checked I7/I8 gates prove built chunks and declarations of all native leaves carry zero optional peer imports and `packages/core/src/` carries zero `streamText`/`generateText` imports; wire-fixture, fault-server, cross-provider switch, and live OpenRouter smoke tests verify protocol correctness.
- `stitchkit/agent-runtime/testing` adds `createScriptedModelDriver`, and the agent starter template drops `ai` and `@openrouter/ai-sdk-provider`.
