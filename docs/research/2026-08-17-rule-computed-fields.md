# Вывод полей контекста из самого правила

## Вопрос

ADR 0078 вывел карту скоупов из синхронного `inject`, который бежит до проверки
правила. Поля, вычисляемые **внутри** async-правила (DB-резолв роли), в
выведенную карту не попадают — крупнейший потребитель держит из-за этого
рукописную карту для своих главных скоупов. Можно ли вывести и их?

## Вердикт: **выражается**, ценой одного узкого поведенческого изменения

Гипотеза расширяется по факту чтения реального кода: боевое правило (`botRule`
потребителя) сообщает отказ **не** через `return false`, а через `throw`
доменной ошибки (`BOT_NOT_FOUND`, чтобы не светить существование ресурса
не-участнику). Значит форма «`false | Fields`» из исходной задачи неполна;
правильная — **`boolean | TFields | Promise<boolean | TFields>`**: `false` →
forbidden, `true` → пропустить без полей, объект → пропустить и смержить,
`throw` → как сегодня.

Типовая механика подтверждена компилируемой пробой
(`scratchpad/rule-fields-probe/probe.ts`, tsc strict, exit 0):

```ts
type FieldsOf<TRule> = TRule extends (...args: never[]) => infer TReturn
  ? Exclude<Awaited<TReturn>, boolean> extends infer TFields extends object
    ? [TFields] extends [never] ? object : TFields
    : object
  : object;
```

- реальный `botRule`, переписанный как «throw для отказа, объект для успеха»,
  выводит `{ botId: string; projectId: string; botRole: Role }` — точно и **без
  второго DB-запроса** (проверка доступа и поля — один резолв, как сейчас);
- boolean-правило выводит `object` (нет объявленных полей) — совместимо;
- union, допускающий `'public'`, выводит `Partial` — правило 0078 переносится;
- async здесь **легален по построению**: правило уже awaited, это ровно та
  граница, где асинхронность живёт — в отличие от `inject`, которому она
  запрещена.

## Ответы на открытые вопросы задачи

- **Совместимость.** Расширение возврата fn-правила — аддитивное для типов:
  существующие `(id) => boolean` присваиваются в widened union; потребительские
  `satisfies Record<Scope, AuthRule<User>>` продолжают компилироваться.
- **Одно узкое поведенческое изменение (назвать breaking):** нетипизированный
  JS-вызов, чьё правило возвращало truthy-объект, сегодня просто проходит
  (`!result` → false); после изменения он пройдёт **и смержит объект в
  контекст**. Класс крайне узкий, но по правилу «никогда молча» — пункт в
  `### ⚠️ Breaking changes`.
- **Двойной правды не возникает.** `inject` и возврат правила объявляют разные
  половины: identity-поля (синхронно, до проверки, есть и у `'public'`) и
  access-производные поля (внутри проверки, только у прошедших). Это не два
  описания одного факта — это два факта. Композиция: merge инжекта, затем merge
  возврата; конфликт ключей — поздний побеждает, задокументировать.
- **`onForbidden`/`onAnonymous`-пути не меняются**: `false` → 403, отсутствие
  identity → 401 до вызова правила, `throw` — пролетает как сегодня.
- **Семантика пустого объекта:** `return {}` — «пропустить, полей нет» —
  эквивалент `true`. Ловушек нет: `{}` truthy и в старом рантайме означал
  пропуск.
- **Двуххуковая композиция** (`AuthScopes<A> & AuthScopes<B>`) не затрагивается:
  вывод остаётся функцией одного `rules`-объекта.

## Эскиз API (для задачи реализации)

1. Расширить fn-ветку `AuthRule<TIdentity>` возвратом
   `boolean | object | Promise<boolean | object>`; в `RuleScopes` добавить
   `FieldsOf` поверх обеих форм (голое правило и `rule` внутри
   `ScopedAuthRule`) с объединением полей inject и возврата.
2. Рантайм в `createAuthHook`: `result === false` → `onForbidden()`;
   `result === true` → pass; объект → `Object.assign(ctx, result)` (thenable
   уже awaited — guard не нужен) → pass.
3. Тесты: реальный сценарий botRule (throw-отказ + поля), boolean-правило без
   изменений, `{}`-возврат, union с `'public'` → Partial, конфликт ключей
   inject/return.
4. ADR — расширение 0078 новым решением (0079): «поля access-производные
   объявляются возвратом правила»; breaking-пункт для truthy-объектов из
   нетипизированных вызовов.

## Приёмка гипотезы на боевом коде

`botRule` потребителя выражается дословно: три `throw` остаются, финальный
`ctx.botId = …; ctx.projectId = …; ctx.botRole = …; return true` заменяется на
`return { botId, projectId, botRole }`. Рукописная карта для `bot`/`project`
становится выводимой; вручную остаётся только `miniAppRuntime` (его поля кладёт
отдельный hook, не auth) — легальный случай пересечения карт, уже описанный в
гайде.
