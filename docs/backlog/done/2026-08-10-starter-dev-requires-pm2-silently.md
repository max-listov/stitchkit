# Starter dev requires pm2 silently

## Зачем

Проверка внешних инструментов в шаблоне сделана образцово ровно один раз и не там,
где важнее всего. `scripts/dev-lan.ts:67` проверяет `mkcert` через `Bun.which` и
даёт подсказку по установке. А `scripts/dev.ts:24` — путь, которым пользуется
**каждый**, — зовёт `pm2 startOrReload` вслепую.

`Bun.spawn` на отсутствующем бинаре бросает **синхронно из конструктора**, а не
возвращает ненулевой код, поэтому ветка с проверкой кода выхода в помощнике
недостижима. Пользователь видит стек с указанием на внутренний помощник; имя `pm2`
в нём есть, но нет ни слова о том, что это требование и как его удовлетворить.
`template/docs/LAN_HTTPS.md` про pm2 не упоминает вовсе, `README.md` — только в
контексте продакшена.

Хуже отсутствия pm2 то, что происходит при **холодном демоне**: `pm2 jlist` печатает
ASCII-баннер в stdout перед JSON (1367 байт, начиная с `\n   -------------`), и
`JSON.parse` падает с `JSON Parse error: Invalid number`. Второй вызов, с прогретым
демоном, отдаёт чистый `[]`. То есть на свежей машине, после ребута или `pm2 kill`
скрипт умирает голым SyntaxError, не называя ни pm2, ни портов.

## Результат

- Отсутствие pm2 сообщается так же внятно, как отсутствие mkcert, и до первого
  побочного эффекта.
- Холодный демон pm2 не ломает разбор его вывода.
- Требование pm2 названо в документации шаблона до первого запуска.
