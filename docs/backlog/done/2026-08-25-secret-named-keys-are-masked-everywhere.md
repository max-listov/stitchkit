# Секрет не утекает в аудит через Map

## Зачем

`packages/core/src/observability/sanitize.ts:113` обещает «secret-named keys
masked», то же самое обещает `docs/guide/observability.md:397`. Маскирование
живёт только в ветке обычного объекта (`sanitize.ts:191`); ветки `Map` и `Set`
(`sanitize.ts:150-166`) зовут `walk()` и `isSensitive` не спрашивают.

Пробник:

```
object: {"headers":{"authorization":"[redacted]"}}
map   : {"headers":{"_type":"map","entries":[["authorization","Bearer sk-live-abc"]]}}
```

`Headers` естественно превращается в `Map`. Обработчик, собравший заголовки
запроса в `Map`, пишет bearer-токен в аудит открытым текстом, тогда как тот же
payload обычным объектом маскируется. Это ровно то правило наоборот: внутрь мы
обязаны знать всё, но секрет в аудит-строке — не «внутрь», это хранилище.

У `Set` ключей нет, поэтому маскировать по имени ключа там нечего — это надо
сказать в тексте прямо, а не оставлять читателя думать, что покрыто и оно.

## Результат

- Значение в `Map` маскируется по своему ключу так же, как поле объекта.
- Вложенность любой глубины: `Map` внутри объекта внутри `Map`.
- Текст говорит, что у `Set` нет ключа и потому нет маскирования по ключу.
