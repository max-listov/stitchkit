# Список Gates выполняет деплой и миграции

## Зачем

Чиня «список Gates нельзя выполнить сверху вниз», я поставил в него
`bun run pm2:prod`. Это ошибка, и опаснее исходной.

`pm2:prod` — не гейт. Он применяет объявленные миграции (`db:deploy`) и делает
`pm2 startOrReload ecosystem.config.cjs` в **дефолтном** PM2-демоне
разработчика. То есть `AGENTS.md` в разделе «перед сдачей работы» велит агенту
мутировать базу и работающий deployment без отдельной команды на деплой — это
прямо ломает границу build → bind.

Рядом два усугубляющих факта:

1. README и AGENTS советуют останавливать роли через `pm2 delete all` — это
   удаляет **все** приложения демона, включая чужие.
2. `pm2` не объявлен зависимостью шаблона и не назван в предусловиях README.
   Свежий скаффолд проходит этот путь только там, где pm2 случайно стоит
   глобально; мой пробник ничего про чистую машину не доказал.

Причина, по которой в списке не осталось `bun run dev`, настоящая: против
dev-сборки 4 из 33 e2e падают на компиляции маршрута по первому запросу. Но
вывод из неё сделан неверный — нужен изолированный harness, а не production.

## Результат

- `check` / `test` / `build` — безопасные гейты над исходником и артефактом.
- `bun run acceptance:local` — изолированный harness: собственный `PM2_HOME`,
  одноразовая база, эфемерные порты, свой allowlist, уборка только того, что
  он поднял. Именно он гоняет `runtime:smoke` и `e2e`.
- `pm2:prod` остаётся отдельной командой деплоя и в списке гейтов не стоит.
- Останов — только по именам ролей из декларации, никогда `all`.
- `pm2` назван предусловием там, где он нужен.
- Фиктивные `alpha.example` / `beta.example` уходят из `_env.example` в
  harness: allowlist продукта перестаёт содержать тестовую фикстуру.
