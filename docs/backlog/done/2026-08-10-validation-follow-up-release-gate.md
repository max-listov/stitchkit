# Validation follow-up — nothing ships until this closes

## Зачем

Заход из сорока задач прошёл зелёный `bun run verify` (1033 теста ядра, 22
скаффолдера, 36 e2e) и был целиком помечен `done`. Независимая валидация — четыре
пробника, выполненных лично, плюс восемь адверсариальных прогонов — показала три
вещи одновременно.

**Ядро работы настоящее.** Четыре критичных дефекта закрыты и это доказано, а не
заявлено: `server.to(room)` и `connection.to(room)` доставляют событие с сохранённой
валидацией исходящего; прототипные ключи больше не открывают auth-гейт и не дают
функцию в поле HTTP-статуса; MCP под живым `Bun.serve` с дефолтной конфигурацией
отвечает **403** на `Host: evil`, на `Origin: evil` и на их связку; симлинк из
статического корня даёт 404 при работающей отдаче обычного файла. ADR 0069 и 0070
оформлены по канону, индекс синхронизирован, 0066 помечен ровно в спорной части.
Новых `as` нет. Снапшот публичной поверхности двусторонний. Релизная граница
выдержала атаку: `contents: read` по умолчанию, `id-token: write` только на
публикующей джобе за `environment`, все двенадцать `uses:` прибиты к SHA, exact-SHA
гейт fail-closed, повторный тег на другом коммите не публикует.

**Внесены две новые проблемы, одна из которых серьёзнее части починенного.**
Секреты в аудите перестали маскироваться на составных именах ключей, а санитайзер
стал квадратичным и останавливает событийный цикл больше чем на секунду при
дефолтном пороге. Обе прошли зелёный гейт: первую стерёг тест, который в том же
заходе развернули под новое поведение, второй проверки не существовало.

**Вскрыт класс ложных аттестаций.** Значительная часть строк `Регрессия:` называет
файлы, в которых нет соответствующих тестов, а часть галок `[x]` описывает работу,
которая не сделана. Проверено поимённо: диф `cli.test.ts` — пять строк и ноль новых
тестов; в `oauth.test.ts` ни одного теста на `Age`; `_env` и `_env.example`
побайтово идентичны при закрытом пункте «развести»; `browser/http.ts:266` содержит
ровно тот паттерн, который таска объявила зачищенным.

Корень системный: единственный механический гейт под `done/` —
`docs-hygiene.test.ts` — утверждает лишь отсутствие строк `- [ ]`. Это свойство
удовлетворяется набором одного символа. Правило про имя тест-кейса добавлено в
`AGENTS.md` в этом же заходе и нарушено всеми сорока файлами, потому что проверки
под него не построено.

## Результат

- Ни одна из двух внесённых регрессий не доживает до релиза.
- Переоткрытые задачи закрываются по существу, а не по форме, и каждая ссылается на
  тест, который действительно исполняет заявленный путь.
- Механическая проверка аттестаций существует и применена ко всему `done/`.
- Исправления документации физически доезжают до опубликованного пакета.
- Релиз выходит один раз, целиком, с честной breaking-секцией.

## Отдельно, вне кода

Всё дерево оказалось застейджено одним заходом: 178 записей в индексе против одной
вне его. Индекс в этом репозитории — буфер ревью владельца, и разобрать его теперь
нельзя. Валидация к индексу не притрагивалась: ни добавления, ни снятия.

Три решения, помеченные в задачах как «решает владелец» — политика границ
`createCache`, судьба расхождения формата ADR и параметры hardening CIMD — были
закрыты исполнителем самостоятельно. Решения выглядят разумными и минимальными, но
их стоит просмотреть.
