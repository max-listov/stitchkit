# Документы обещают больше, чем гарантирует код

## Зачем

Заголовок схемы декларации уже переписан честно: **структура — гарантия**
(значения места положить некуда), **гигиена — фильтр** (`namesAMachine` ловит
известные формы, а не всё). Но соседние документы остались на прежнем,
абсолютном утверждении, и читатель получает более сильное обещание, чем код
даёт:

- `docs/VISION.md:88` и `packages/create-stitchkit/template/README.md` —
  «схеме некуда их положить».
- README и AGENTS шаблона говорят о **трёх** порождаемых файлах, а их четыре:
  два `ecosystem*.cjs`, блок `env.variables` и `app-identity.generated.ts`.
- `build-inputs.ts:23` в комментарии трактует отсутствие объявленных входов как
  «сборка не читает данных». Печатает он верное — «не читает **объявленных**
  данных»; неверен комментарий. Механика правильная: декларация — это
  утверждение автора, а гейт проверяет объявленное.
- `CHANGELOG.md`: после раскатки ссылка `[Unreleased]` осталась
  `compare/v0.60.0...HEAD`, должна считать от `v0.60.1`.
- GitHub пометил `create-stitchkit-v0.4.0` общим repository “Latest”, из-за чего
  релиз ядра визуально не последний. Для двух независимых линий нужно управлять
  `make_latest` при создании GitHub Release.

## Результат

- Каждый документ описывает ту гарантию, которую код действительно даёт.
- Счёт порождаемых файлов совпадает с тем, что проверяет `declaration.test.ts`.
- Ссылки чейнджлога согласованы с раскатанной версией.
- Релиз ядра помечается latest в своей линии.
