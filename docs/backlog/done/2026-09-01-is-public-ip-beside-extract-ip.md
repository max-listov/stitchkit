## Зачем

`extractIp` и `trustProxy` мы уже владеем: адрес клиента извлекается в одном
месте. Следующий вопрос — можно ли этот адрес отдавать наружу (резолвить у
третьей стороны, ходить по нему, записывать как источник запроса) — остался у
потребителя, и два проекта написали одну и ту же таблицу зарезервированных
диапазонов.

Забывают в такой таблице никогда не `10/8`. Забывают carrier-grade NAT
(`100.64/10`) — настоящий клиентский адрес, до которого нет маршрута обратно, —
и `169.254/16`, то, что хост отвечает, когда DHCP не отработал.

## Результат

- Ответ живёт рядом с `extractIp`, откуда берётся сам адрес.
- Неразбираемое значение — НЕ публичный адрес: иначе первый же кривой заголовок
  проходит как публичный, а это ровно тот случай, ради которого функция и есть.

## План

- [x] `isPublicIp` в `server/request.ts`, экспорт из `stitchkit/server`.
- [x] Полный набор IANA special-purpose для IPv4, без `node:net` — ядро
      остаётся Web Fetch-clean (ADR 0013).
- [x] IPv6 — правилом, которое не стареет, а не перечислением исключений.

## Acceptance

- [x] Границы блоков проверены с обеих сторон, включая `172.16/12`, чья граница
      не лежит на границе октета.
- [x] `240/4` отвергается: беззнаковый сдвиг, иначе весь блок читается как
      отрицательный и проходит.
- [x] Неразбираемое значение и пустая строка дают `false`.

## Что сделано

### Core
- [x] `isPublicIp` в `packages/core/src/server/request.ts`: пятнадцать
      IPv4-блоков; собственные парсеры IPv4 и IPv6 (компрессия `::`, зона
      `%eth0`, встроенный IPv4) без `node:net`.
- [x] IPv6 сформулирован обратным правилом: публичен только global unicast
      `2000::/3`, минус IETF assignments и documentation. Перечисление
      исключений было бы списком, который стареет; это правило не может
      пропустить диапазон, который ещё не назначили.
- [x] Адрес с ведущим нулём (`010.0.0.1`) не разбирается: одни резолверы читают
      его как восьмеричный, другие как десятичный, и это два разных хоста.
      Адрес, чей смысл зависит от читателя, мы не подтверждаем.
- [x] IPv4-mapped (`::ffff:10.0.0.1`) судится как несомый им IPv4 — именно в
      этом виде приходит socket peer на dual-stack listener.
