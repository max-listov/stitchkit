# Release notes одной версии описывают два взаимоисключающих состояния

## Зачем

`0.4.1` ещё не выпущена, и её раздел писался в два захода. В первом я чинил
невыполнимый список гейтов и записал, что список **теперь называет**
`bun run pm2:prod`. Во втором — по замечанию аудита — убрал деплой из гейтов и
записал, что список **больше не деплоит**. Обе записи остались рядом
(`CHANGELOG.md:19` и `:65`), и то же противоречие лежит между двумя секциями
`UPGRADING.md` (`:91` и `:128`).

Промежуточное состояние никогда не выпускалось. Release notes описывают
версию, а не путь, которым автор к ней шёл: читатель, следуя им сверху вниз,
сначала добавит `pm2:prod` в свой список гейтов, потом уберёт.

Рядом два меньших расхождения того же рода:

- `docs/VISION.md` имеет `updated: 2026-08-23`, хотя правился сегодня.
- `docs/guide/upgrading.md` идёт `0.49.0 → 0.46.0 → 0.48.0 → 0.47.0`: читатель,
  которому сказано «прочти всё в диапазоне», получает диапазон вразнобой.

## Результат

- В `[0.4.1]` и в миграции 0.4.1 остаётся ровно одно описание конечного
  состояния гейтов.
- Даты и порядок разделов соответствуют фактам.
