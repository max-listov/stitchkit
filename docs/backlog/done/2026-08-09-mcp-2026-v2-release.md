# MCP 2026-07-28 / SDK v2 — зонтичный релиз

## Зачем

Stitchkit `0.43.1` уже делает MCP stateless по умолчанию, подготавливает
immutable tool surfaces и создаёт свежий request context, однако wire runtime
остаётся на монолитном `@modelcontextprotocol/sdk@1.x`. В коде всё ещё живут
`Mcp-Session-Id`, stateful session/event stores, ручные v1 HTTP/stdio transports
и публичные v1 SDK-типы.

TypeScript SDK v2 и спецификация `2026-07-28` уже stable. Откладывание означает
развивать удаляемый session layer, а поздняя миграция затронет больше
потребителей. Переход выполняется одним явно breaking minor-релизом без
параллельного Stitchkit API, aliases и compatibility wrappers.

## Результат

- Stitchkit обслуживает MCP `2026-07-28` через официальные v2 serving entrypoints.
- HTTP core не хранит protocol sessions и может работать за обычным round-robin.
- Один endpoint принимает modern clients и официальный legacy-stateless fallback.
- Prepared surfaces, auth/RBAC, lifecycle, hooks, validation, Apps и multimodal
  content сохраняют существующие гарантии.
- Modern wire получает routing headers, deterministic discovery и честные cache
  hints.
- Runtime tools могут безопасно запросить пользовательский ввод через MRTR.
- OAuth provider понимает Client ID Metadata Documents как канонический механизм
  регистрации modern clients.
- Потребитель получает механическую before → after миграцию и полный upgrade audit.

ведётся параллельно, но закрывается последней по фактическому API.

## Архитектурные решения

- **Один framework API.** Публичные `createMcpHandler`, `buildMcpServer`,
  `createStdioMcpServer`, `rawTools` и `McpServer` меняются на v2 в существующих
  именах; рядом не появляются `V2`-варианты.
- **Stateless HTTP — единственный Stitchkit mode.** `sessionMode`, session map,
  event replay и `Mcp-Session-Id` удаляются.
- **Legacy только на wire boundary.** Совместимость 2025-era реализует официальный
  SDK handler в stateless-режиме на том же endpoint; Stitchkit не содержит свой
  legacy router или transport.
- **Одинаковая compatibility policy на обоих транспортах.** HTTP использует
  официальный `legacy: 'stateless'`, stdio — официальный `legacy: 'serve'`.
  Legacy HTTP sessions/SSE не возвращаются; modern-only deployment может выбрать
  `legacy: 'reject'` через одну общую policy, не через второй API.
- **Точный публичный transport control.** `createMcpHandler()` возвращает
  `{ fetch, close }`: `fetch` монтируется как route, `close` отменяет незавершённые
  modern requests и освобождает transport. `createStdioMcpServer()` возвращает
  `StdioServerHandle`-совместимый `{ close }`. SDK `notify`/`bus` не экспортируются,
  пока Stitchkit не поддерживает `subscriptions/listen`.
- **State — доменная сущность.** Долгие операции используют явный handle/task ID;
  многораундовый ввод — opaque MRTR `requestState`, а не server memory.
- **MRTR не заменяет server push.** Modern HTTP MRTR покрывает только продолжение
  конкретного tool call. Resumable SSE, cross-request push и server-owned pending
  workflows удаляются; legacy-stdio shim допускается лишь там, где его реально
  поддерживает SDK/host.
- **Web Fetch-clean.** Core использует `@modelcontextprotocol/server`; Node adapter
  подключается только там, где Web API недостаточно, и не протекает в browser-safe
  entrypoints.
- **Extensions независимы.** MCP Apps сохраняются extension layer; Tasks и
  `subscriptions/listen` не входят без потребительского кейса.
- **CIMD ортогонален transport cutover.** После фикса публичной auth/config границы
  его можно реализовывать параллельно modern semantics/MRTR; релизный gate общий.
- **Node floor не меняется.** SDK v2 требует Node 20+, Stitchkit сохраняет свой
  более строгий публичный минимум Node 22+.

## Compatibility matrix

| Surface | Modern HTTP | Legacy HTTP | Modern stdio | Legacy stdio |
|---|---:|---:|---:|---:|
| Tool/resource discovery and calls | да | да, stateless | да | да |
| MCP Apps resource/tool metadata | да | да | да | да |
| MRTR `input_required` | да | нет, fail-first `-32021` | да | только официальный session-capable SDK shim |
| Session resume / unsolicited server push | нет | нет | нет | не является Stitchkit API |
| `subscriptions/listen` | не заявляется | не заявляется | не заявляется | не заявляется |

## Не входит

- MCP Tasks extension и собственная background task model.
- `subscriptions/listen`, пока нет реального notification consumer.
- Новые Roots, Sampling или Logging APIs: core-варианты deprecated.
- Собственный MCP client framework и client-side response cache store.
- Миграция потребительских репозиториев внутри этого репозитория.
