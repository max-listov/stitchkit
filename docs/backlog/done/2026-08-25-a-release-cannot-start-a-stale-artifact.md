# pm2:prod проверяет существование артефакта, а не его свежесть

## Зачем

`scripts/release.ts` зовёт `assertBuildArtifacts()`, а тот проверяет, что пути
из `build.artifacts` существуют. Существование — не свежесть: `pm2:prod`,
запущенный без предшествующего `build`, применит новую миграцию из этого
источника и поднимет `dist` и `.next` от прошлого. Схема уйдёт вперёд кода —
самая неприятная форма рассинхрона, потому что откат кода её не отменяет.

Найдено сторонним аудитом; в этом заходе не исправлялось.

## Результат

- Релиз отказывается стартовать на артефакте, который старше источника,
  из которого он якобы собран, и говорит, что пересобрать.
- Признак — факт, а не догадка: отпечаток источника, записанный сборкой рядом
  с артефактом, либо сравнение времён, у которого нет ложноположительных на
  чистом checkout.

## Acceptance

- [x] `pm2:prod` на устаревшем артефакте падает до применения миграций.
- [x] `bun run verify` зелёный.

## Что сделано

- [x] `packages/create-stitchkit/template/scripts/build-stamp.ts` (новый):
      `sourceDigest()` — один sha256 по каждому файлу, который сборка читает,
      с путём в хеше (перенос файла меняет сборку, не меняя ни байта внутри);
      `writeBuildStamp()` в конце `bun run build`;
      `assertArtifactMatchesSource()` в `assertBuildArtifacts()`.
- [x] **Digest, а не время.** Checkout переписывает все mtime, форматтер
      переписывает часть без изменений — обе ситуации дали бы ложный отказ, а
      гейт, которому перестают верить, хуже отсутствующего.
- [x] Список исключений описывает то, что не может повлиять на артефакт
      (`node_modules`, `.git`, `.next`, `dist`, `generated`, `.env*`, `*.md`,
      тесты, `next-env.d.ts`). Всё остальное считается — поэтому новый исходный
      файл покрыт самим фактом своего существования, а не записью в списке.
- [x] Отсутствие штампа — отказ, а не «считаем свежим»: значит артефакт собран
      чем-то другим, и «мы не можем определить» не основание его запускать.
- [x] `.build-stamp.json` в `_gitignore`.
- [x] `scripts/build-stamp.test.ts` — 7 тестов: правка исходника, новый файл,
      перенос файла, безвредность README/`.env`/тестов, безвредность
      generated- и installed-деревьев, отсутствующий штамп.
