# Каждый публичный origin отвечает на один вопрос

## Зачем

После перевода примера на дефолтную одноисточниковую форму осталась неровность,
которую поймал владелец при разборе: `PUBLIC_API_ORIGIN` **выглядит как
переключатель режима** — «браузер набирает API по этому адресу», — а на деле его
читал только realtime-сокет. HTTP-клиент константа с `/api` и на переменную не
смотрит вовсе.

Это тот же класс дефекта, что `close()` и `onResourceFailure` в этом же заходе:
**текст обещает механику, которой нет.** Здесь текстом является имя переменной,
и цена та же — оператор ставит её, ожидая, что переключил режим, а переключил
одну из двух вещей.

Вопросов действительно два, и они независимы, потому что независим транспорт:
HTTP web-роль умеет переслать сама, а WebSocket-апгрейд через route handler не
проходит. Значит deployment может быть одноисточниковым по HTTP и всё равно
обязан назвать адрес сокета. Одна переменная на два ответа не бывает честной.

## Результат

- У сокета собственная переменная `PUBLIC_REALTIME_ORIGIN`. Не задана — сокет
  идёт на origin страницы, где маршрутизатор отдаёт `/socket.io`.
- `PUBLIC_API_ORIGIN` означает ровно HTTP и ничего больше; сам по себе он режим
  не переключает, и это сказано там, где его читают.
- Обе опциональны: deployment за одним маршрутизатором не поставляет ни одну.
- Переключение на кросс-доменный HTTP — один импорт в `queries.ts`, и цена
  (ленивый клиент, скобки, порядок относительно `<Providers>`) названа рядом.

## Что сделано

### Шаблон — обе переменные говорят правду

- [x] `packages/config/src/variables.ts`: `PUBLIC_REALTIME_ORIGIN` заведён рядом
      с `PUBLIC_API_ORIGIN`, и у каждой написано, на какой вопрос она отвечает и
      почему вопросов два — HTTP web-роль умеет переслать, WebSocket-апгрейд
      через route handler не проходит. `INTERNAL_API_URL` и `CORS_ORIGIN`
      переформулированы там же: первый никогда не виден браузеру, второй нужен и
      для HTTP, и для realtime-рукопожатия.
- [x] `packages/frontend/src/env.ts` проецирует новую переменную; порождённый
      `project.json` объявляет её вместе с остальными (`bun run gen:declaration`).
