# Вывод полей контекста из самого правила

## Зачем

ADR 0078 вывел карту скоупов из `inject` правила и провёл честную границу:
`inject` синхронный и бежит **до** проверки правила, поэтому поля, которые
вычисляются **внутри** async-правила, в выведенную карту не попадают. Крупнейший
потребитель попадает в эту границу своими главными скоупами: его `bot`/`project`
правила резолвят из БД каноничный `botId`, `projectId` и `botRole` — ровно в
момент проверки доступа — и пишут их в контекст сами. Эти скоупы остались на
рукописной карте, то есть класс дефекта «карта разъезжается с хуком» для них не
закрыт, а он у них основной.

## Гипотеза для проверки

Правило-функция возвращает не `boolean`, а `false | TFields`:

```ts
bot: {
  rule: async (client, ctx) => {
    const access = await resolveBotAccess(client.id, String(ctx.botId));
    if (!access) return false;
    return { botId: access.canonicalBotId, projectId: access.projectId, botRole: access.role };
  },
},
```

`true`-ветка несёт поля → хук мержит их в контекст → `RuleScopes` выводит тип
из возвращаемого union. Проверка доступа и вычисление полей происходят там, где
они и происходят фактически — в одном DB-запросе, без второго резолва.

## Что исследовать (не решать заранее)

- [x] **Совместимость:** `boolean`-правила остаются как есть; отличима ли
      `false | TFields` форма от текущей без breaking (правило, возвращающее
      `true`, не несёт полей — как это выражается в `RuleScopes`: `object`?).
      Опасный угол: правило, возвращающее truthy-объект, где раньше ждали
      строгий `boolean` — приведение и семантика «пустой объект = пропустить».
- [x] **Порядок с `inject`:** у правила уже есть `inject` (синхронный, до
      проверки). Композиция полей из обеих половин: конфликт ключей, порядок
      мержа, `Partial` для `'public'`-union — распространяется ли на
      rule-computed поля (public-правило функцией не бывает? бывает — union).
- [x] **`onForbidden`-путь:** `false` → 403 как сейчас; `никакого identity` →
      401 до вызова правила — не меняется.
- [x] **Двойная правда:** не появляется ли снова два места объявления полей
      (inject И возврат правила) — возможно, форма с возвратом должна
      **заменять** `inject` в объектном правиле, а не дополнять.
- [x] **Реальный код потребителя** как приёмочный критерий: его `botRule` /
      `projectRule` должны выражаться без рукописной карты и без второго
      DB-запроса; двуххуковая композиция (`AuthScopes<A> & AuthScopes<B>`)
      должна пережить новую форму.
- [x] Если гипотеза подтверждается — отдельная задача реализации с ADR
      (расширение 0078 или новый); если нет — записать причину в исследование и
      закрыть, граница в ADR 0078 остаётся.
