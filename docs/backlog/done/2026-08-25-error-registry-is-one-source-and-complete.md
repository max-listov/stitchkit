# Реестр кодов ошибок — один источник, и он полон

## Зачем

**1. Четыре кода фреймворка отсутствуют в реестре.** Перебор всех
`new AppError('CODE'` в `packages/core/src` против `contract/errors.ts:118`:

```
DOWNLOAD_NOT_FOUND   tools/define-download-tool.ts
VIEW_HTTP_ERROR      tools/view-file.ts
WAIT_FAILED          tools/define-wait-tool.ts
WAIT_TIMEOUT         tools/define-wait-tool.ts
```

Реестр объявлен как «code → HTTP status для кодов, которые бросает **сам
stitchkit**», ADR 0026 — как «один источник правды». Для этих четырёх
`isStitchErrorCode` возвращает `false`, поэтому и `codeMap`, и резолвер
`unmappedCode` их пропускают: код уезжает на провод так, будто его бросил проект.
Потребитель, отобразивший «все коды фреймворка», молча промахивается мимо четырёх.

**2. `docs/guide/auth-and-errors.md:417` перечисляет 17 из 18** — нет
`APPLICATION_NOT_ACCEPTING` — и абзац, который роняет добавление, заканчивается
обещанием «каждое добавление названо в changelog». Ниже, на `:437`, лежит
`Record<StitchErrorCode, AppCode>` без него же: скопированный сниппет **не
компилируется**. Это тот самый блок, который агент потребителя находит в
`llms-full.txt`.

**3. `packages/core/src/server/error-hook.ts:60` обещает исчерпывающую карту** —
«Exhaustive — `satisfies Record<StitchErrorCode, …>` makes a new framework code a
compile error here» — прямо над `codeMap?: Partial<Record<…>>`. Шапка того же
модуля (`:6`) говорит обратное. JSDoc уезжает в `.d.ts`, то есть это первое, что
видит потребитель по наведению.

**4. Разворот записан только в коде.** `docs/decisions/0026-…md:54` до сих пор
обещает, что пропущенный код станет ошибкой компиляции; 0.56.1 сделал карту
частичной. По правилу `AGENTS.md` архитектурное решение требует ADR и строки в
индексе — ни того, ни другого нет.

## Результат

- Реестр содержит каждый код, который бросает фреймворк, и статус у каждого.
- Guide перечисляет ровно то, что в реестре, и приведённый map компилируется.
- Ни один текст не обещает исчерпывающей карты над частичной.
- Разворот 0.56.1 записан как решение, а не как факт кода.
