# S6 — файлы супервизии становятся производными

## Зачем

`ecosystem.config.cjs` и `ecosystem.dev.config.cjs` сегодня написаны руками и
отличаются друг от друга девятью строками, каждая из которых — либо факт про
код (какой файл запускать, нужен ли `--watch`), либо политика места
(`autorestart`, `kill_timeout`). Пока оба файла ручные, факт про код существует
в двух экземплярах, и они уже разошлись — см. S5.

Это последняя стадия, где контур перестаёт быть рукописным. Она идёт после S3,
S4 и S5, потому что порождать файл можно только из декларации, которая уже
умеет описывать роли, форму приезда порта и пол слива.

## Результат

- Оба файла порождаются: роли, команды и форма запуска — из декларации;
  супервизия и пути — со стороны места. Проверка «не редактируется руками»
  становится машинной, а не договорённостью.
- Строка `pm2:prod` в `package.json` перестаёт быть источником: миграция
  выводится из типизированного ключа `release` (S3), а преflight сборки
  `ensure-built` переезжает в `build`, которому он и принадлежит.
- **Ручной путь сохраняется целиком.** Проект, у которого нет никакой внешней
  стороны места, поднимается теми же `bun run dev` и `bun run start:api` /
  `start:web`, что и сегодня. Порождение — удобство, а не условие запуска.
- `scripts/dev.ts` перестаёт дублировать список переменных
  (`dev.ts:88-99`) — он выводит его из декларации.

### Исправление предыдущей записи

Первая версия этого раздела утверждала, что `pm2:prod` перестал быть
источником, что `ensure-built` живёт в `build`, и что ручной путь работает
целиком. Ни одно из трёх не было правдой на момент записи: строка оставалась
рукописной, `ensure-built` лежит в `start`, а `bun run dev` не запускался ни
разу. Всё три теперь сделаны и проверены — запись выше описывает состояние,
а не намерение.

### Что показал настоящий прогон

Файлы супервизии были собраны и проверены структурно, но ни один гейт не
запускает pm2, поэтому форма запуска ни разу не исполнялась. Исполнение нашло
дефект, которого структурная проверка увидеть не могла: с командой
`bun run <script>` роль получает сигнал остановки **дважды** — от супервизора
и от лаунчера, — второе нажатие форсирует слив, и объявленные 15 секунд
превращаются в 1.3 мс (`Shutdown forced (signal)`), а единственным следом
остаётся ненулевой код выхода. После перевода команд ролей на прямой exec:
`Shutdown clean`, код 0. Веб-роль отдельно перестала рапортовать 130 на
запрошенной остановке.

Закреплено: `scripts/declaration.test.ts::a role starts its own process, never
a launcher`, комментарий в `ProjectRoleSchema.commands` и раздел
`docs/guide/testing-and-deployment.md::Let the supervisor start the role, not a
launcher`.
