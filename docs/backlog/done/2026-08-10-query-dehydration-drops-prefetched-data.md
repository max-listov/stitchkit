# Query dehydration drops all prefetched data

## Зачем

```ts
// template/packages/frontend/src/lib/query-client.ts:8
shouldDehydrateQuery: (query) => query.state.status === 'pending',
```

Опция **заменяет** дефолт библиотеки, а не дополняет его (проверено в
установленном `@tanstack/query-core@5.101.4`, `hydration.js:51-62`). Замер на
реальной версии: конфигурация шаблона дегидратирует **0** запросов, каноническая —
1.

Дефолт библиотеки отбирает успешные запросы; замена его условием «в процессе»
означает, что успешно полученные на сервере данные в конверт гидратации не попадают
вовсе. Это живёт и в поставляемом примере:
`examples/repository/…/page.tsx:29-35` ждёт `prefetchQuery`, а гидратировать нечего
— на каждой загрузке страницы клиент делает повторный запрос и показывает вспышку
загрузки. То есть серверный префетч выполняется, стоит времени и всё равно
бесполезен.

## Результат

- Успешно полученные на сервере данные доезжают до клиента и рендерятся без
  повторного запроса и без вспышки загрузки.
- Поведение «дегидратировать также запросы в процессе», если оно нужно, выражено
  как **дополнение** к дефолту, а не как его замена.
