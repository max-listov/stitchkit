# Зелёное дерево не должно проходить полный гейт второй раз

## Зачем

Замер релиза 0.60.1 / 0.4.1 / 0.4.2:

| | |
| --- | --- |
| весь релиз, от команды до последней публикации на npm | 33 м 48 с |
| из них локальный `pre-push` (три пуша) | **18 м 58 с** |
| те же проверки на CI (три рана) | 7 м 06 с |

Первый пуш стоил 7 м 16 с и **не принёс ни одного нового факта**: его дерево
совпадало с тем, которое `bun run verify` признал зелёным несколькими минутами
раньше. Ровно та же работа, ровно те же байты.

Причина в том, что гейт ничего не помнит. Он привязан к событию (пуш), а не к
тому, что он на самом деле проверяет, — к содержимому дерева.

## Результат

- Локальный гейт помнит последний зелёный результат по хешу **содержимого**
  дерева (`git write-tree`), а не по коммиту, ветке или времени.
- Совпал хеш — дорогая часть пропускается с явной строкой о том, какой прогон
  за неё отвечает; не совпал — выполняется полностью.
- Метаданные релиза (тег, версия, subject, changelog) проверяются **всегда**:
  они дешёвые и зависят не от дерева.
- CI это не ослабляет ни на грамм: он как был единственным авторитетом для
  публикации (`select-ci-run` на точном SHA), так и остаётся.

## План

- [x] Хеш дерева считать по рабочему дереву, а не по индексу: индекс
      принадлежит владельцу и не отражает то, что гейт проверял.
- [x] Запись зелёного результата класть вне репозитория (кеш машины), чтобы она
      не попадала ни в дерево, ни в поставку.
- [x] В запись включить версию тулчейна: тот же исходник на другом Bun — другой
      прогон.
- [x] Пропуск печатает, что именно пропущено и по какому прогону, — молчаливый
      пропуск гейта неотличим от отсутствующего гейта.

## Acceptance

- [x] Второй подряд пуш неизменённого дерева не запускает дорогую часть.
- [x] Любая правка файла в дереве возвращает полный прогон.
- [x] `bun run verify` зелёный.

## Что сделано

### Tooling
- [x] `scripts/gate-memo.ts` — запись зелёного прогона: ключ = хеш содержимого
      рабочего дерева + отпечаток тулчейна (`bun:… node:… platform/arch`).
      Ни коммит, ни ветка, ни время в ключ не входят.
- [x] Хеш снимается через одноразовый `GIT_INDEX_FILE`: настоящий индекс
      принадлежит владельцу и не открывается даже транзиентно.
- [x] Запись живёт в кеше машины (`$XDG_CACHE_HOME/stitchkit/green-gates.json`),
      кольцо на 8 записей; повреждённый файл читается как пустой и никогда не
      разрешает пропуск.
- [x] `scripts/verify.ts` — гейт стал списком шагов вместо `&&`-цепочки в
      `package.json`; профили `full` / `fast` / `head`, флаг `--if-changed`.
      Зелёный `verify` засчитывается и за `verify:fast` (полный прогон
      выполняет каждый быстрый шаг).
- [x] Пропуск печатает, что именно пропущено, каким прогоном и когда.
- [x] Запись — о дереве, с которого прогон **начался**; если шаг изменил дерево,
      это печатается и мемо на новое дерево не распространяется.
