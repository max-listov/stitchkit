# Всё обновлено до последних версий, и обновление вскрыло два гейта

## Зачем

Подготовка к релизу по одной команде: дерево должно быть на текущих версиях, а
не «почти». Обновление здесь — не косметика, это ещё и проверка того, что
гейты держат само обновление.

## Результат

- Ядро, скаффолдер и шаблон на последних релизах, ни одного пересечённого мажора.
- `peerDependencies` ядра не тронуты.
- Оба гейта, которые обновление сломало, починены по корню, а не по симптому.

## Что сделано

- [x] Обновлено: Next 16.3.2, `next-intl` 4.13.7, `@tanstack/react-query`
      5.102.3, `@tanstack/react-table` 9.1.2, `framer-motion` 13.1.1,
      `@wrksz/themes` 1.2.0, `shiki` 4.4.3, `sonner` 2.0.8, `ai` 7.0.78,
      `pg` 8.23.0, Playwright 1.62.1, Biome 2.5.10, `oxc-parser` 0.147.0,
      `@types/*`. Корневые и шаблонные диапазоны выровнены.
- [x] `peerDependencies` ядра оставлены как были (`ai ^7.0.0`, `srvx ^0.12.5`,
      `@types/bun ^1.3.14`, `@tanstack/react-query >=5`). Поднятый пол — это
      ужесточение требования к потребителю, то есть слом, и он стоил бы минора

- [x] `biome.json` в корне и в шаблоне указывают на схему установленной версии
      (2.5.10) — рассинхрон печатал info в каждом прогоне линта.

### Гейт 1: `bun update --latest` растворяет каталог

`bun update --latest` переписал `"stitchkit": "catalog:"` в литеральный диапазон
**во всех шести манифестах шаблона сразу**. Это ровно то, что запрещает правило
релиза: диапазон называется в одном месте, `catalog.stitchkit`, потому что
релиз стартера двигает одно число, а копия где угодно ещё — это второе число,
способное разойтись.

Гейт на это был, но его список манифестов написан руками и уже отстал: он
называл три файла из шести, и `packages/config`, добавленный в этом же заходе,
в него не входил. То есть молча растворить каталог было можно.

- [x] `scripts/starter-manifest.ts`:
      `assertCatalogIsTheOnlyStitchkitRange()` обходит **каждый** манифест
      дерева и проверяет все три секции зависимостей;
      `scripts/starter-lane.ts` зовёт её вместо списка из трёх путей.
- [x] `scripts/starter-manifest.test.ts` (5 тестов), в том числе тот самый
      манифест, которого не было в старом списке. Проверено на убийство:
      с подменённым ожиданием тест падает.
- [x] Каталог восстановлен во всех пяти местах, `bun.lock` шаблона пересобран.

### Гейт 2: тест, прибитый к версии чужого пакета

`scaffold.test.ts::ships one server-first theme implementation` требовал
`"@wrksz/themes": "^1.1.0"` буквально. Тест про то, что реализация темы **одна**,
а падал он на числе, к этому свойству отношения не имеющем, — то есть каждое
плановое обновление стоило бы ложного красного.

- [x] Утверждение теперь про зависимость, а не про её релиз: пакет присутствует
      с любым caret-диапазоном, конкурирующего пакета нет.

### Настоящий слом в зависимости

- [x] `@wrksz/themes` 1.2 сменил дженерик `useThemeValue` с типа **значения** на
      тип **карты** и добавил `const`-вывод. Явный аргумент на месте вызова стал
      расширять результат до всех членов `string`, и шаблон перестал
      компилироваться. Вызов отдан выводу типов —
      `packages/frontend/src/components/ui/toaster.tsx`. Записано в
      `packages/create-stitchkit/CHANGELOG.md`, потому что существующий
      сгенерированный проект встретит то же самое.
