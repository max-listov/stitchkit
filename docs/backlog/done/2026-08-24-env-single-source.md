# S7 — env.required не становится третьей копией схемы окружения

## Зачем

Ключ `env.required[]` перечисляет имена и форму значений. Против кода шаблона
это означает **третью** копию: схема окружения уже описана дважды и частично
пересекается сама с собой.

- `packages/config/src/server.ts:11-24` — серверная схема: `DATABASE_URL`,
  `BIND_HOST`, `API_PORT`, `WEB_PORT`, три URL, `LOG_FORMAT`, `CORS_ORIGIN`.
- `packages/frontend/src/env.ts:9-13` — фронтовая схема, переобъявляющая
  `INTERNAL_API_URL`, `WEB_PORT` и два публичных URL.
- `scripts/tooling-env.ts:9-12` — тулинговая схема, переобъявляющая ещё два.

Три файла уже расходятся по составу. Записать те же имена руками в декларацию —
значит завести четвёртый, и нарушить седьмой пункт собственной границы: «всё
выводимое из уже объявленного не повторяется».

## Результат

- Декларация **выводит** `env.required[]` из Zod-схемы, а не хранит копию.
  Направление вывода — часть стадии: либо схема остаётся источником и
  декларация порождается, либо декларация становится источником и схема
  строится из неё.
- Рекомендация — первое. Схема уже несёт `default`, `coerce` и сообщения об
  ошибках, которых в декларации быть не должно; терять их ради машинной
  читаемости — плохой обмен.
- Три схемы сводятся к одной с проекциями на серверную, фронтовую и тулинговую
  части. После S2 публичных имён в ней не остаётся, что делает сведение
  дешевле, — поэтому S7 идёт после S2, а не параллельно ей.
- Секреты в декларации не появляются ни как значения, ни как имена,
  подразумевающие конкретное хранилище.
