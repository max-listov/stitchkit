# Tests written for the last eleven releases can actually fail

## Зачем

Набор тестов вырос до 1554 и в целом сильный: гонки, fencing, терминальные
переходы покрыты содержательно. Но в свежей партии есть четыре места, где тест
формально существует, а удерживать поведение не может. Каждое опасно тем, что
создаёт ложное чувство покрытия — включая закрытые задачи, где эти тесты
названы регрессией.

**Потерянный `await`.**
`packages/core/tests/managed-resource-conformance.test.ts:144-151` —
`expect(runManagedResourceConformance({…, scenarios: []})).rejects.toThrow(…)`
без `await` внутри `async`-теста. Промис ассерта теряется: убрать валидацию из
кита — тест останется зелёным. Это единственный такой случай в наборе, и он в
самом свежем conformance-ките.

**Opt-in из breaking-релиза без покрытия.** `includeInternalCause`
(`agent-runtime/observability.ts:52`, `:89`) — половина breaking-изменения
0.58.0, ровно граница «внутренние причины наружу не уходят». Ни одного
вхождения в тестах: покрыт только дефолтный, редактированный путь. Инвертировать
флаг — не упадёт ничего.

**Тест-тавтология вместо регрессии на фикс.** 0.59.2 чинил rebind
Fetch-заблокированного порта (`server/node.ts:104-127`). Единственный
относящийся тест — `node.test.ts:49-52`:
`expect(isFetchBlockedPort(4045)).toBe(true)` — проверка поиска по
захардкоженному множеству, которое сам тест и импортирует. Вызова
`serveNode({ port: 0 })` нет ни одного: удалить весь блок rebind — сьют зелёный.
При этом `docs/backlog/done/2026-08-23-application-public-proof.md` называет
именно этот тест регрессией, а `docs-hygiene.test.ts` проверяет лишь, что
названный тест **существует**, не что он относится к делу.

**Флейки-тест в отгруженном коде.** `packages/core/tests/application-kernel.test.ts`
case `forces resources concurrently against one pair of absolute deadlines`
падает примерно в четырёх прогонах из десяти. Измерено на чистом дереве тега
`v0.59.4`, без каких-либо правок: 10 прогонов дали 4 падения; на дереве с
текущими изменениями — те же ~40%. Это не последствие правок и не соседний
эффект: тест нестабилен сам по себе, а нестабильный тест хуже слабого — он
приучает игнорировать красный прогон.

**Непройденный happy path.** `agent-runtime-fence.test.ts:21-52` идёт только по
ветке отказа и утверждает `expect(settled).toBe(0)`. Ветка успеха
(`managed-tools.ts:52-57`, `afterHandle` возвращает результат и зовёт
`onSettled`) не исполняется: удалить её — сьют зелёный. При этом
`docs/guide/agent-runtime.md:307` предписывает «Always compose
`toolFenceLifecycle`».

## Результат

- Каждый из четырёх тестов падает, если удалить код, ради которого он написан.
- `includeInternalCause` покрыт с обеих сторон: включённый показывает причину,
  выключенный — нет.
- Фикс port-rebind удерживается тестом, который поднимает сервер, а не сверяет
  константу с самой собой.
- Закрытые задачи, ссылавшиеся на неудерживающие тесты, получают ссылку на
  настоящую регрессию — новой задачей, без правки иммутабельных документов в
  `done/`.
