# Гейт, который не выполнился, — не «зелёный»

## Зачем

Худший вид проверки — та, что зеленеет именно тогда, когда не сработала.

**1. `packages/core/scripts/consumer-lane/run.mjs:72` — `tsc()` возвращает пустую
строку и на успехе, и на несостоявшемся запуске.** Пустая строка — сигнал «чисто».
Пробник на `execFileSync`:

```
missing binary: {"status":null,"signal":null,"joined":""}
killed child  : {"stdout":"","stderr":"","status":null,"signal":"SIGKILL","joined":""}
```

То есть если `tsc` убит OOM-киллером в контейнере CI или бинарь не найден,
полоса печатает «the published package works for a consumer» и выходит с нулём —
для всех четырёх фикстур, и для strict-typecheck, и для declaration-проверки.

**2. `packages/core/scripts/check-env-live.mjs:25` — `.some(f => f.includes('NODE_ENV'))`.**
Любой `.js` в dist, любое вхождение подстроки. Сейчас свойство держится
случайностью: вхождение ровно одно. Второе — например список известных ключей в
типизированном env-хелпере — и гейт зеленеет навсегда, включая тот день, когда
бандлер свернёт настоящее чтение и формат логов замёрзнет у всех потребителей.
Текст рядом (и ADR 0040) утверждает биекцию: «если чтение выжило, строка в
бандле; если свернулось — строки нет».

**3. Тесты, которые не могут упасть.**
- `packages/core/tests/request-logging.test.ts:105` — `lines` не передан в
  handler, `expect(lines).toEqual([])` неопровержим.
- `packages/core/tests/execute.test.ts:280` — `hooks` не вызывается; единственная
  исполняемая проверка `expect(hooks).toBeDefined()` на литерале двадцатью
  строками выше.
- `packages/core/tests/app-error-brand.test.ts:64` — `try` без `throw` после
  вызова: если `badRequest` перестанет бросать, тест зелёный.
- `app-error-brand.test.ts:42` и `api-error-brand.test.ts:48` — бренд объявлен
  через `Symbol.for`, поэтому `Object.keys()` не вернёт его никогда.
- `byte-range.test.ts:71` — сравнение чистой функции с самой собой.
- `tool-name-validation.test.ts:105` дублирует `utils.test.ts:32`.

**4. `packages/core/tests/no-fixed-ports.test.ts:22` — заголовок говорит «tests/ и
scripts/», в `ROOTS` корневой `scripts/` отсутствует.** Сегодня там `port: 0`, но
гейт не заметил бы обратного.

**5. `scripts/release-plan.ts:265` — `assertVersionCalibre` молча пропускает
версию, которой нет в списке заголовков вида `## [x.y.z]`.** `## [0.56.1-rc.1]`
проходит notes-проверку и пропускает гейт «breaking в патче».

## Результат

- Несостоявшийся запуск отличается от чистого прогона и валит полосу.
- Проверка окружения привязана к выражению, а не к подстроке.
- Ни один тест не проходит из-за того, что проверяемое не выполнялось.
- Гейт портов смотрит туда, где действительно поднимаются серверы.
