# Readiness gate for runtime adapters and canonical examples

## Зачем

`to(room)` вышел сломанным, и документация учила его вызывать
(`docs/guide/realtime.md:62`). Разбор показал, что артефакты процесса были на
месте: шесть done-файлов, гайд, reference, CHANGELOG, пять тестов **и**
автоматический потребитель (`packages/core/scripts/node-smoke.mjs:92` выполняет
`bindRealtimeServer` через установленный пакет).

Сломались две конкретные вещи.

**1. Галка о покрытии соврала, и проверить её было нечем.**
`docs/backlog/done/2026-08-10-contract-first-realtime.md:53` утверждает, что
комнаты покрыты в `socket-io.test.ts`. В realtime-блоке теста (строки 122–252)
`to()` не вызывается ни разу; `realtime.onConnection(({ events }) => {` (`:145`)
даже не деструктурирует `to`. Гайд, тесты, smoke и галка написаны одним проходом с
одной ментальной моделью — `to()` выпал из неё во всех четырёх сразу.

**2. Дефект был в форме кода.** Фабрика требовала от цели способностей, которые
доказуемо не будут использованы (`inbound: {}`, тип цели `Pick<…, 'emit'>`).
Ленивый резолв убирает класс без единого теста.

**Измерено, что часть напрашивающихся механизмов бьёт мимо.** Типочек примеров
документации этот баг не видит: сниппет `to(room).emit(...)` типопроверяется
идеально, потому что типы верны, а сломана реализация. Массовое исполнение всех
блоков гайда неприменимо: из 168 `ts`-фенсов компилируется ноль, 23 не парсятся
вовсе — блоки задуманы обучающими фрагментами. Инвентарь экспортов сам по себе
тоже не ловит: `tests/reference-coverage.test.ts` уже перечисляет экспорты всех
восьми точек входа и был зелёным, `bindRealtimeServer` есть в `reference.md:258`,
а `to` — вообще не экспорт, а метод возвращаемого объекта.

Требование «живой потребитель на каждый публичный экспорт» из этой задачи
**исключено осознанно**: 64% поверхности — типы (193 значения против 331 типа,
411 уникальных имён), для которых рантайм-потребитель бессмыслен, а для остальных
требование удовлетворяется вызовом, ничего не доказывающим о форме аргументов.
Догфуд как ценность остаётся, но живёт там, где у него есть доменный смысл, —
в `example-adopts-contract-first-realtime`.

Цена в CI не ограничение: замер по последним прогонам — 4.5 минуты wall clock,
перечисленные ниже проверки добавляют 5–15 секунд (типочек 145 файлов на TS7 —
0.34 с).

## Результат

- Рантайм-адаптер над нетипизированной целью имеет объявленный список
  поддерживаемых форм, и каждая форма покрыта тестом.
- Утверждение о покрытии невозможно сделать прозой — только ссылкой на файл и имя
  теста.
- Канонический пример подсистемы исполняется, а не пересказывается.
- Снапшот публичных экспортов падает и при добавлении, и при удалении имени.

## План

- [x] **Матрица возможностей для рантайм-адаптеров.** Там, где методы достаются
      через `Reflect.get` у нетипизированной цели, модуль объявляет список
      поддерживаемых форм цели явно (для realtime это `Server`, `Socket`,
      `BroadcastOperator`). Список — данные, а не комментарий.
- [x] **Тест на каждую форму** из объявленного списка. Приоритетно закрыть дыру
      типом: `target: { emit: … } & Partial<{ on: …; off: … }>` делает жадный
      guard невыразимым, и тесты становятся обычными юнит-тестами вместо правила,
      которое надо помнить.
- [x] **`Что сделано` ссылается на тест.** Каждый пункт про покрытие называет файл
      и имя теста; прозаическое «покрыто» запрещено. Строка в `AGENTS.md` рядом с
      разделом о бэклоге — тулинга не требует, а это ровно сломавшееся звено.
- [x] **Исполняемые канонические примеры.** Направление авторства перевёрнуто: не
      вытаскивать прозу в компилятор, а генерировать прозу из протестированного
      кода. Ключевой пример подсистемы живёт настоящим файлом, тест его компилирует
      и **исполняет**, гайд трансклюдит регион, отдельная проверка требует
      байтового совпадения фенса с источником — тот же класс, что работающий
      `reference-coverage.test.ts`. Область — один канонический пример на
      подсистему, не все 168 блоков.
- [x] **Двусторонний снапшот публичной поверхности.** Переиспользовать
      `ts.createProgram` + `getExportsOfModule` из `scripts/check-public-types.mjs`,
      ключевать по уникальному имени (`index.ts` делает `export *` из `contract`,
      иначе каждая правка контракта двоит записи). Снапшот обязан падать и на
      удалении: сегодня `reference-coverage.test.ts` односторонний
      (`экспорт ⊆ задокументировано`), поэтому молча выпавшее из бочки имя
      оставляет тесты зелёными.
- [x] Согласовать с `deterministic-single-pass-releases`: проверка секции changelog
      принадлежит ей. Диф поверхности требует сборки, поэтому живёт в branch CI /
      `verify`, а tag-preflight остаётся тонким.

- [x] Снапшот поверхности падает и при добавлении, и при удалении имени.
- [x] Ни одна из проверок не реализована как напоминание в документации.

## Не входит

- Требование живого потребителя на каждый публичный экспорт: 64% поверхности —
  типы, а для значений требование удовлетворяется вызовом, ничего не доказывающим.
- Исполнение всех 168 блоков гайда — измеренная стоимость несоразмерна, и этот
  класс дефектов типочек не видит.
- Требование ADR на каждый публичный экспорт — `AGENTS.md` требует ADR на
  **решение**, а не на экспорт.
- Замедление релизного темпа как отдельная мера.

## Переоткрыто 2026-08-10 — по итогам валидации

Задача была закрыта преждевременно. Ниже — что проверено и оказалось неверным, и что
осталось сделать. Галки выше отражают заявленное на момент закрытия и сохранены как
запись; истина — в этом разделе.

**Правило добавлено и тут же нарушено сорок раз.** `AGENTS.md:48` требует называть
точный файл **и имя тест-кейса**. Все сорок файлов, ушедших в `done/`, называют файл
плюс прозаическое описание — то есть ровно ту форму, которая делает ложную аттестацию
возможной и которую правило вводилось запретить.

- Acceptance `[x] Файл, уходящий в `done/`, не может утверждать покрытие прозой` и
  `[x] Ни одна из проверок не реализована как напоминание в документации` —
  **взаимно противоречивы и оба ложны**: единственный артефакт — строка-напоминание
  в `AGENTS.md`, механической проверки нет.
- Единственный существующий гейт `docs-hygiene.test.ts` утверждает ровно одно:
  под `done/` нет `- [ ]`. Это свойство удовлетворяется набором одного символа.

Аудит показал: механическая проверка формы `файл::имя-кейса` с подтверждением, что
кейс существует, поймала бы **восемь** ложных аттестаций этого захода.
