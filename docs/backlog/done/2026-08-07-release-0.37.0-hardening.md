# Release 0.37.0 — native tools and hardening pass

## Why one release

The project reached 0.36.1 through a dense sequence of pre-1.0 releases. The
next approved scope includes deliberate callback/configuration breaks and a new
native registration surface. Ship the work as one reviewed 0.37.0 migration
instead of making controlled consumers cross another chain of minors.

This task coordinates the release; implementation details remain in the linked
tasks and are not duplicated here.

## Integration plan

1. Repair and validate the dependency/tooling foundation first: TypeScript 7
   CLI plus the official semantic API package, current peers, optional MCP Apps
   coverage and deterministic starter versions. This makes later gates trusted.
2. Finalize `ToolCallHooks` as options objects and record its ADR before adding
   another runner-backed API. New native tooling starts with the final callback
   contract rather than being migrated twice.
3. Build one deterministic MCP preparation and validation foundation: the
   object-shaped schema profile, portable-format walker and measured immutable
   descriptor cache. Validation and advertised schemas must share one surface.
4. Build framework-owned native registration on that final runner, hook and
   prepared-schema foundation; then perform the real multimodal/lifecycle/audit
   consumer migration and concurrency E2E.
5. Switch HTTP configuration to `sessionMode` with stateless as the default,
   reusing prepared descriptors so the safer default does not introduce
   per-request schema compilation or shared request state.
6. Fix `enrich` precedence and finish the Node declaration/Fetch-purity guard.
   These are independent correctness gates but ship in the same migration.
7. Refresh API/guide/upgrading/generated-LLM docs alongside each public change,
   then reconcile VISION and ROADMAP after the final surface is known. Any new
   architecture decision gets an ADR plus index row before implementation.
8. Run focused tests while developing only when explicitly authorized, then run
   the repository's single final `bun run verify` gate after the complete scope.
9. Pack and exercise the release through the consumer lane. Update every
   owner-controlled consumer in the same pass and run the reported native-tool
   E2E audit scenario before calling the release ready.
10. Lead `CHANGELOG.md` with `### ⚠️ Breaking changes`, including mechanical
   migrations for hook options objects, schema validation and `sessionMode`;
   group additive fixes, performance work and documentation separately.
11. Bump `packages/core/package.json` to 0.37.0 only after implementation and
   migration checks are complete. Commit, push, tag, publish and deploy remain
   separately gated actions and are not authorized by this plan.

## Deliberate exclusions

- SDK-rejected invalid calls remain an honest observability boundary until the
  SDK exposes a public interception seam. The proposal is preserved in
  [`icebox`](../icebox/2026-08-07-sdk-rejected-tool-observability.md), not
  implemented by replacing the protocol dispatcher.
- Transport-dependent contract variants remain explicit twin operations; two
  current cases do not justify a magical per-transport handler contract.
- Chat history policy, response formatting, entity registries, persistence
  models, model catalogs and domain dimensions remain application concerns.
