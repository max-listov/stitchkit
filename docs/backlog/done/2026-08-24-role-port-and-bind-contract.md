# S4 — роль объявляет, как к ней приезжает порт и интерфейс

## Зачем

Декларация предполагает, что роль называет **имя переменной**, через которую
окружение впрыснет порт. Проверено против шаблона: для одной роли это верно,
для другой — нет.

- API-роль читает порт из окружения: `port: env.API_PORT`
  (`packages/backend/src/index.ts:30`). Имени переменной достаточно.
- Веб-роль порт из окружения **не читает**. Он передаётся ей аргументом
  командной строки: `args: ['start', '--port', process.env.WEB_PORT, ...]`
  (`ecosystem.config.cjs:17-23`, то же в `ecosystem.dev.config.cjs:7-13`).
  Переменную читает не роль, а файл супервизии.

Разница не косметическая. Если сторона места впрыснет `WEB_PORT` в окружение
процесса и на этом остановится, веб-роль поднимется не на том порту — молча.

Тот же вопрос со стороны интерфейса. API-роль объявляет `hostname: env.BIND_HOST`
(`packages/backend/src/index.ts:31`, значение по умолчанию `127.0.0.1` в
`packages/config/src/server.ts:15`), веб-роль получает `--hostname` тем же
аргументом. Имя переменной привязки в декларации не предусмотрено вовсе.

## Результат

**Решение принято на уровне флота: обе роли читают порт из окружения. Форма
«аргумент командной строки» в декларацию не вносится.** Причина шире исходной
рекомендации: альтернатива обязывает сторону места уметь две формы впрыска
навсегда, ради одного исключения. Интерфейс привязки объявляется тем же
способом — именем переменной.

Против кода это оказывается меньшей правкой, чем выглядело. Веб-роль **уже**
читает окружение в своей собственной команде:
`"start": "next start --port ${WEB_PORT:-3210}"` (`packages/frontend/package.json`).
Аргумент строит сама команда роли — это её внутреннее дело. Ломает контракт не
она, а файл супервизии, который команду роли обходит: `ecosystem.config.cjs`
запускает `node_modules/.bin/next` напрямую и собирает `args` руками
(строки 17-23), из-за чего `WEB_PORT`, впрыснутый в окружение процесса,
роль не достигает.

- Файлы супервизии вызывают **объявленную команду роли**, а не собственный
  argv. После этого впрыска переменной достаточно для обеих ролей.
- `BIND_HOST` объявляется как переменная привязки для обеих ролей; веб-роль
  получает `--hostname` из неё внутри своей же команды.
- Умолчание порта из репозитория исчезает. `${WEB_PORT:-3210}` — номер порта,
  лежащий в `package.json`, то есть значение, различающееся между deployment'ами,
  в файле репозитория. Отсутствующая переменная обязана валить запуск с
  внятной ошибкой, а не тихо поднимать роль на чужом порту.
