# Уборка баз считает localhost доказательством общего pid-пространства

## Зачем

Я написал, что уборка «действует только на фактах», и тут же сделал вывод из
хоста: `starter-database.ts:91` считает `localhost`/`127.0.0.1` доказательством
того, что pid в имени принадлежит этому ядру. Это неверно для SSH-туннеля,
port-forward, Docker/VM-моста и нескольких runner'ов через локальный прокси.

В таком сценарии pid чужого **живого** прогона на этой машине выглядит мёртвым.
Если его база в этот момент без подключений — а между шагами она без
подключений минутами, — уборка выполнит `DROP DATABASE`. Для разрушающей
операции имя хоста фактом не является.

Рядом: rollback при `CREATE ROLE`/`CREATE DATABASE` останавливается на первой
ошибке уборки и может не закрыть SQL-соединение — устойчивость применена к
`dispose()`, но не к откату создания.

## Результат

- Владение доказывается не хостом, а именем: в имя базы и роли входит
  устойчивый идентификатор машины (machine-id + boot-id). Запись, помеченная
  чужой машиной, кандидатом не становится никогда.
- pid трактуется только для записей своей машины.
- Rollback создания пробует все шаги и всегда закрывает соединение.

- [x] Убрать вывод из хоста как основание для разрушающей операции.
- [x] Rollback создания — по образцу `dispose()`.
- [x] Тесты: запись чужой машины не кандидат даже при мёртвом pid и нуле

## Acceptance

- [x] Уборка не может удалить базу, созданную не на этой машине.
- [x] `bun run verify` зелёный.

## Что сделано

- [x] Владение доказывается именем, а не хостом: в `sk_lane_<ns>_<pid>_…`
      входит `<ns>` — восемь hex из boot-id (запасной вариант — machine-id,
      затем случайный на процесс). Pid — факт об одном работающем ядре, и
      только запись своего пространства имён вообще становится кандидатом.
- [x] Вывод из `localhost` удалён. Уборка теперь работает и против общего
      сервера, потому что безопасность даёт имя, а не догадка о хосте.
- [x] Rollback создания приведён к той же форме, что `dispose()`: все шаги
      пробуются, соединение закрывается всегда, отказы агрегируются.
- [x] Тест на запись чужого пространства имён: не кандидат даже при мёртвом
      pid и нуле подключений.

### Проверка на живой машине

- [x] Рядом посажены две записи: чужого пространства имён и своего с мёртвым
      pid. Один прогон удалил **только своё**; чужое осталось нетронутым.
