# S8 — совместимость декларации проверяется, а не подразумевается

## Зачем

После S1–S7 репозиторий несёт машинно-читаемую декларацию, которую читает
сторона места. Между ними появляется контракт, и у контракта два способа
сломаться молча: сторона места понимает не ту версию схемы, и артефакт
оказывается непереносимым, хотя декларация утверждает обратное.

Оба способа лечатся одинаково — проверкой, которая падает, а не
предупреждает. Репозиторий уже держит этот стандарт для своих границ:
`scripts/release-plan.ts` отвергает тег, не стоящий на релизном коммите, а
`packages/core/tests/reference-coverage.test.ts` отвергает точку входа,
которой нет в документации. Декларация должна попасть в тот же режим.

## Результат

- Версия схемы декларации проверяется **fail-closed** с обеих сторон:
  репозиторий с версией, которой сторона места не понимает, отвергается с
  внятной ошибкой, а не обслуживается частично. Умолчания «наверное подойдёт»
  нет ни в одну сторону.
- Ошибка совместимости называет, чего именно не хватает, и остаётся внутренней:
  наружу не уезжает ничего про устройство стороны места.
- Переносимость артефакта доказывается в packed-полосе, а не заявляется:
  один собранный артефакт обслуживается по двум разным внешним адресам без
  пересборки. Это прямое продолжение S2 и единственная проверка, которая
  ловит возврат привязки к месту.
- Проверка декларации входит в `bun run verify`, а не живёт отдельной
  командой, которую можно забыть.
