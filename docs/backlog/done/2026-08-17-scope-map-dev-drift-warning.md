# Dev-предупреждение о дрейфе карты скоупов

## Зачем

Пока карта скоупов пишется руками (и даже после вывода из хука — для
приложений с рукописной картой), расхождение «объявлено X, инжектится Y»
обнаруживается только багом. Потребитель, нашедший расхождение в четырёх
скоупах из шести, указал на точный прецедент в нашем же коде:
`warnOnOutputStrip` ловит дрейф «хендлер вернул больше, чем объявляет контракт».
Это тот же класс дефекта, зеркально — на входной стороне контекста.

Задача — тактическое дополнение к выводу карты из хука
(`2026-08-17-scope-map-derived-from-auth-hook.md`), не замена: вывод убирает
дрейф по построению там, где есть хук; предупреждение ловит его везде.

## Результат

- Опциональный dev-режим (по образцу `warnOnOutputStrip`): после `authorize` /
  `inject` фактические ключи, добавленные в контекст, сравниваются с полями,
  объявленными для эффективного скоупа эндпоинта.
- Расхождение — предупреждение с именами: скоуп, эндпоинт, чего не хватает /
  что лишнее. Один раз на комбинацию, не на каждый запрос.
- Ноль накладных в проде: выключено по умолчанию, включается явно.

## Открытый вопрос дизайна

Рантайм не знает **типовую** карту (она стирается). Значит, либо
`createScopedImplement` получает опциональный рантайм-довесок с именами полей
(риск: снова два описания), либо предупреждение строится только на выведенной
из хука карте (тогда задача сливается с родительской). Решить в ADR
родительской задачи, не плодить отдельного решения.
