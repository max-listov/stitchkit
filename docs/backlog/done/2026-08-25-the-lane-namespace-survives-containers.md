# Пространство имён уборки баз не различает контейнеры одного ядра

## Зачем

Прошлая правка заменила вывод из `localhost` на идентификатор загрузки — это
было верное направление, но выбранный факт недостаточен. `boot_id` — свойство
**ядра**, а контейнеры одного ядра его разделяют, имея при этом **разные
PID-пространства**. Значит pid живого процесса соседнего контейнера снова
выглядит мёртвым отсюда, и его база без подключений снова становится кандидатом
на `DROP DATABASE`.

Pid — факт о PID-пространстве, а не о ядре. Именно оно и должно входить в
идентичность.

Отдельно: текст задачи говорил «machine-id + boot-id», а код выбирает одно из
двух через `??`. Расхождение между обещанием и реализацией здесь опаснее
обычного, потому что операция разрушающая.

## Результат

- Идентичность — digest из идентификатора загрузки **и** инода
  PID-пространства (`/proc/self/ns/pid`), а не одного из них.
- Если доказуемой идентичности получить нельзя, межпрогонная разрушающая
  уборка выключается, а не выполняется на догадке.
- Документ и код говорят одно и то же о том, что входит в идентичность.

## Что сделано

### Scripts

- [x] `scripts/starter-database.ts`: `laneNamespaceDigest({ bootId,
      pidNamespace })` — чистая функция, digest по **обоим** фактам; отсутствие
      любого возвращает `undefined`.
- [x] `pidNamespace` читается как `readlinkSync('/proc/self/ns/pid')`

- [x] `LANE_SWEEP_ENABLED` выключает межпрогонную разрушающую уборку, когда
      доказуемой идентичности нет; `sweepAbandonedLaneDatabases` в этом случае
      возвращается с явной строкой в лог, а не работает на догадке.
- [x] Комментарий модуля описывает ровно то, что делает код: `??` между двумя
      фактами больше нет.

### Регрессия

- [x] `scripts/starter-database.test.ts`, блок `the namespace is what makes a
      pid readable`: один boot-id и разные PID-пространства дают разные
      namespace; запись соседа не кандидат, как бы мёртво ни выглядел её pid;
      одинаковые факты дают одинаковый digest; отсутствие любого факта — не
      digest; эта машина свою идентичность доказывает (иначе уборка молча
      выключена).

### Решение, записанное вместо lease/heartbeat

- [x] Lease/heartbeat в таблице Postgres рассмотрен и отклонён: он вводит
      состояние, которое само нужно убирать, и переносит вопрос «жив ли
      владелец» на «свежий ли heartbeat» — тот же вопрос с новым таймаутом.
      Идентичность из фактов ОС не требует состояния и остаётся верной, когда
      процесс убит SIGKILL. Пересмотреть, если появится общий Postgres, к
      которому лэйны ходят из разных ядер.
