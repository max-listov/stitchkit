## Зачем

Обход соседних проектов дал две находки одной природы — обе про протоколы
платформы, которые владелец платформы опубликовал, а мы не отдали.

**Проверка `initData`.** Три бэкенда написали её сами; два файла явно имеют
общего предка и с тех пор разошлись. Алгоритм короткий и опубликованный —
именно поэтому его переписывают, и именно поэтому нормальный исход «почти
правильно»: сравнение, возвращающееся на первом различающемся байте; срок
годности, проверенный раньше подписи; `initDataUnsafe`, уехавший прямо в сессию.
Каждая из трёх ошибок читается как рабочий код.

**Классификация отказа отправки.** Два бота делят broadcast-подсистему (три
файла байт-в-байт), и внутри неё один список подстрок решает сразу два вопроса:
повторять ли отправку и продолжать ли вообще писать этому получателю. Один
список на два вопроса не отвечает — сообщение, которое Telegram не смог
распарсить, это дефект нашего payload, а засчитывается получателю.

Ни то ни другое не domain model (ADR 0002): «Telegram подписал эту строку» —
факт о транспорте, того же сорта, что корректный bearer token.

## Результат

- Поверхность, отдающая обе вещи, не требует ни бот-библиотеки, ни kernel'а.
- Отказ проверки называет причину, а не возвращает `false`: просроченная строка
  и подделанная — разные факты, и приложение отвечает на них по-разному.
- Классификация отказа отправки разводит «повторить эту отправку» и «перестать
  писать этому получателю» в два отдельных ответа.

## План

- [x] Выбрать дом: не `application/grammy` (бросает при отсутствии peer и
      возвращает `ManagedResource`), не `stitchkit/server` (ядро остаётся
      generic) — новый leaf `stitchkit/telegram`, server-only, peer-free.
- [x] `verifyTelegramInitData`: подпись через Web Crypto, сравнение digest'ов
      без раннего выхода, проверка подписи ДО чтения чего бы то ни было из
      строки, включая `auth_date`.
- [x] `classifyTelegramSendFailure` по образцу `classifyProviderFailure`
      (ADR 0141): reason + evidence, без формулировок для человека.
- [x] Обвязка нового entrypoint: `package.json`, `build:server`,
      `reference-coverage`, `optional-peer-matrix`, `getting-started`, справочник,
      снапшот публичной поверхности, VISION.

## Acceptance

- [x] Подпись, собранная НЕЗАВИСИМОЙ реализацией (`node:crypto`), принимается
      модулем на Web Crypto — утверждение о согласии двух стеков, а не о
      согласии модуля с самим собой.
- [x] Подделанная строка со старым `auth_date` возвращает `signature-mismatch`,
      а не `expired`.
- [x] Отказ, который не опознан, НЕ помечает получателя недоступным.

## Что сделано

### Core
- [x] `packages/core/src/telegram/init-data.ts` — `verifyTelegramInitData`:
      HMAC через Web Crypto, constant-time сравнение hex-digest'ов,
      `maxAgeSeconds` как явная граница (по умолчанию границы нет — это решение
      приложения, а не наше), инъектируемые часы, camelCase-пользователь через
      `.transform()` и все подписанные пары в `raw`.
- [x] `packages/core/src/telegram/send-failure.ts` —
      `classifyTelegramSendFailure`: восемь причин, `retryable` и
      `recipientUnreachable` как ДВА отдельных ответа, `retryAfterSeconds`
      только когда Telegram его назвал, evidence `parameters | status |
      description | none`.
- [x] `packages/core/src/telegram.ts` — barrel; entrypoint `stitchkit/telegram`
      в `package.json` и в `build:server`.

### Tests
- [x] `packages/core/tests/telegram-init-data.test.ts` — девять случаев;
      подпись строится `node:crypto`, то есть другой реализацией.
- [x] `packages/core/tests/telegram-send-failure.test.ts` — восемь случаев,
      включая «наш сломанный payload не стоит нам получателя» и цикл в `cause`.
- [x] `VerifyTelegramInitDataOptions` внесён в `option-effects` — каждая
      объявленная опция называет тест, который её исполняет.
- [x] Две строки в `optional-peer-matrix`: Bun и Node. Вторая не ради
      симметрии — Web Crypto единственный глобал, который между этими двумя
      рантаймами мог бы отличаться.

### Docs
- [x] ADR 0143 + строка в индексе; `docs/api/reference.md`;
      `docs/guide/getting-started.md` (строка зрелости + таблица peer);
      `docs/VISION.md`; `CHANGELOG.md` 0.71.0; снапшот публичной поверхности.

### Что не делалось
- [x] Скопированные фронтовые `useTMA`-хуки — не берём: frontend infrastructure
      остаётся вне фреймворка (записано в ADR 0143).
- [x] Валидация третьей стороной (Ed25519 `signature`) — не понадобилась ни
      одному наблюдённому потребителю; место для неё готово, решение
      пересматривать не нужно.
- [x] Полный broadcast-раннер (аудитория, resumable state, pacing) — правило
      двух выполнено, но это уже подсистема с собственным хранилищем, а не
      функция над значением; отдельная задача, если спрос подтвердится.
