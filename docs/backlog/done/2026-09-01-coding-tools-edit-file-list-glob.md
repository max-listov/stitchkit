## Зачем

Наблюдение за прогоном девяти моделей разного класса на одной задаче: правка через `apply_patch`
со строгим форматом не далась половине из них. Не найдя способа изменить файл, модели
перезаписывали его целиком через `write_file` — с потерей несохранённых частей и всеми отказами
перезаписи. Правка заменой точной строки (`old_string` → `new_string`) — форма, которую сегодня
понимает любая модель: она короче, ошибки в ней локальны, а неоднозначность разрешается
удлинением сниппета.

Листинга и поиска по маске в наборе нет вовсе — модели обходились через shell, где есть, и
оставались слепы, где его нет.

## Результат

Набор coding tools отвечает на три вопроса, которые модель задаёт каждый ход:

- `edit_file(path, old_string, new_string, replace_all?)` — ноль вхождений и множественные
  вхождения отклоняются с называнием причины и счётчиком; `replace_all` заменяет все.
- `list_directory(path)` — записи с типом и размером.
- `glob(pattern, path?)` — файлы по маске, отсортированные, без `node_modules`.

Все три уважают ту же границу корня, что и остальной набор.

## Ресерч 2026-09-01

Главная поправка к «Зачем», прочитанная из исходника: **`apply_patch` уже сегодня работает формой
`oldText → newText → replaceAll`** (`coding-tool-search-patch.ts`), никакого diff-формата в нём нет.
«Строгий формат», не давшийся половине моделей, — это три другие вещи:

1. обязательный `baseSha256` — модель обязана донести 64-hex digest из последнего `read_file`;
2. `dryRun: true` по умолчанию — правка требует ДВУХ вызовов, второй с `dryRun: false`, и из схемы
   этот протокол не выводится;
3. штатные отказы `Coding patch text was not found` / `is not unique` брошены plain `Error` и
   доезжают до модели как пустой `INTERNAL_SERVER_ERROR` — модель не может выучить протокол из
   ответов инструмента.

Референс — харнес, в котором написан этот план: его `edit_file` работает потому, что отказ
инструктивен («not found», «found 3 matches — provide a larger unique snippet or replace_all»),
digest не требуется (свежесть обеспечивает сам `old_string`: он не совпадёт с изменившимся файлом),
а правка применяется одним вызовом.

Решение об одном чистом пути (AGENTS: no dual paths). `edit_file` НЕ добавляется рядом с
`apply_patch` — он ЗАМЕНЯЕТ его переопределением семантики на evolving-поверхности:

- `edit_file(path, oldText, newText, replaceAll=false, expectedSha256?, dryRun=false)` — имена
  параметров в camelCase, как у всей поверхности; snake_case первой редакции был скопирован из
  референсного харнеса и ломал конвенцию;
- digest опционален, но если передан — проверяется как сейчас (`conflict` на stale);
- **инвариант конкурентности**: чтение файла, подсчёт вхождений и построение результата
  выполняются ВНУТРИ `withCodingPathLock`, от свежего содержимого. Без этого удаление
  обязательного digest открывает lost update, которого сегодня нет: два конкурентных
  `edit_file` по разным сниппетам одного файла оба построят полное содержимое от v0, и вторая
  запись сотрёт первую. Лок — per-process `Map`: девять агентов в одном процессе покрыты, два
  процесса на одном workspace — нет; ограничение записывается в doc инструмента;
- **выход специфицирован**: `{path, sha256 (нового содержимого), replacements, bytes, applied}` —
  возвращённый digest позволяет следующей правке чейниться `expectedSha256` без повторного
  чтения (`read_file` уже возвращает `sha256` — цепочка замыкается);
- payload authorize-операции `edit` сохраняет способности `patch`-операции: `resultSha256`,
  `resultBytes`, `replacements`, `dryRun` — host-политика не теряет ни одного рычага;
- ноль вхождений → typed отказ с нулём и советом проверить точность сниппета; N>1 без
  `replace_all` → typed отказ с точным N и советом удлинить сниппет; оба — коды, не
  INTERNAL_SERVER_ERROR (зависимость от таски про opaque failures);
- внутренности переиспользуются целиком: `textOccurrences`, `withCodingPathLock`, атомарная замена.

`list_directory` и `glob` строятся на существующем `scanContainedFiles` (та же граница, те же
exclude-каталоги, что у `search_files`). Для glob НЕ берётся внешняя зависимость: поддерживается
достаточное подмножество `**`, `*`, `?` собственным компилятором маски (≈30 строк), это решение
записывается в ADR вместе с заменой apply_patch.

Авторизация: union `AgentCodingToolAuthorizationSchema` получает операции `edit`, `list`, `glob`
(`patch` уходит вместе с инструментом). Breaking здесь трёх сортов, и худший — не тот, что виден
компилятору:

1. исчерпывающий switch с never-проверкой — compile error, заметен;
2. **неисчерпывающий матчер — тихий**: при default-allow новые операции молча авторизованы, хотя
   хост их не утверждал (расширение прав без ведома); при default-deny флагманский `edit_file`
   молча мёртв. Migration обязана прямо предписать: обработайте `edit`, `list`, `glob` явно,
   ветка `patch` мертва;
3. строковые policy по имени инструмента — approval-policy шаблона стартера ключуется именем
   `apply_patch` (`templates/agent/src/runtime.ts:123`) и молча умирает; шаблон правится в том же
   заходе, а едет отдельным релизом `create-stitchkit` со своим CHANGELOG/UPGRADING.

Калибр — **минор 0.71.0** (breaking двигает минор). Гейты потребуют: `**Who must act:**` первой
строкой breaking-секции; `## Unreleased migration:` точной формы в `docs/guide/upgrading.md`
с цепочкой обеих волн (`coding_edit_file → apply_patch → edit_file` — потребитель 0.68→0.71
мигрирует одну правку дважды, migration обязана это признать и дать прямой переход);
перегенерация cadence-предложения в `docs/guide/getting-started.md`; обновление
`docs/api/reference.md`, `docs/guide/agent-runtime.md` (§ упоминаний apply_patch), TUI-теста
`controller.test.ts:170`, `public-surface.json`.

## План

- [x] `edit_file` в форме из ресерча; `apply_patch` удалён; ADR о переопределении + строка в
      индексе; migration в `docs/guide/upgrading.md` (before → after, digest опционален).
- [x] `list_directory(path='.')`: записи `{name, kind: file|directory|symlink, bytes?}`,
      каталоги-первыми; лимит записей — ИМЕНОВАННЫЙ (`maxListEntries` в
      `AgentCodingToolLimitsSchema`, регистрация в option-effects); усечение НЕ молчаливое:
      `truncated`-флаг в выходе; exclude-каталоги помечаются, не скрываются.
- [x] `glob(pattern, path='.')`: отсортированный список путей; выход несёт `truncated` И
      `skippedDirectories` — модель, глобящая дерево, где всё живое в excluded `dist/`, обязана
      видеть, что каталоги были пропущены, иначе пустой список читается как «файлов нет».
      Развести в выходе «результат обрезан» и «дерево не досканировано» (у `scanContainedFiles`
      это сегодня один флаг — расширяется).
- [x] Авторизация: новые операции в union; тест, что `authorize` получает каждый вызов.
- [x] Тесты по образцу acceptance ниже + фальсификация ревертом каждого правила.

## Acceptance

- [x] Правка файла проходит одним вызовом `edit_file` без digest и без dry-run-церемонии; с
      переданным `expected_sha256` stale-состояние по-прежнему отклоняется как `CONFLICT`.
- [x] Неоднозначная замена отклоняется с количеством вхождений и советом удлинить сниппет.
- [x] Выход за корень через КАЖДЫЙ из трёх новых инструментов отклоняется typed-кодом с
      workspace-relative текстом — не `INTERNAL_SERVER_ERROR` (сегодняшний escape доезжает именно
      им; старый общий тест зелёный заранее и нового поведения не различает).
